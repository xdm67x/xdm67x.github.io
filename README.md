# xdm67x.github.io

Personal portfolio for **Mehmet Ozkan** — software engineer, AI tooling,
computer graphics.

Four full-frame slides sit over one looping film of a night sea. Moving between
them is a single hard transition: the page is torn into bands and pushed through
the lens, then the next one lands oversized, snaps into place behind a flash and
a shockwave. The same choreography plays in a live 3D scene behind the page, on
the same clock.

Everything three-dimensional is generated in **Rust**, compiled to
**WebAssembly**, and drawn with **WebGPU** (through `wgpu` + WGSL). The film is
generated by a dependency-free Rust program too. There is no game engine, no 3D
asset pipeline, and no JavaScript build step.

## Stack

| Piece | What it does |
| --- | --- |
| `renderer/` | Rust crate: procedural meshes, the four arrangements of glass pieces, the destruct/reconstruct transition, lighting, and the projection of the world labels the DOM pins into the scene. Compiled to wasm with `wgpu` on the WebGPU backend. |
| `web/` | The front end: plain ES modules (`main.js`, `data.js`, `style.css`). No bundler, no transpiler. |
| `index.html` | The document. All content is real, accessible DOM. |
| `tools/loopgen.rs` | The background film: a seamless 12 s loop of a night sea, written to raw frames and encoded with ffmpeg. A development tool, not part of the build. |
| `public/film/` | The encoded loop and its poster, shipped as a plain `<video>` source. |
| `Trunk.toml` | The entire build: Trunk compiles the crate, resolves the wasm-bindgen version matching `Cargo.lock`, copies `web/` and `public/film/`. |

`wgpu` is used rather than raw WebGPU calls so the renderer keeps a normal Rust
shape: typed pipelines, one uniform block, instanced draws.

## Run it

```bash
trunk serve             # http://127.0.0.1:8080, rebuilds and reloads on edits
trunk build --release   # production build into dist/
```

Only two tools are needed: [Trunk](https://trunkrs.dev) and the Rust
`wasm32-unknown-unknown` target. Trunk downloads the matching `wasm-bindgen` CLI
itself, so there is no version to pin by hand.

```bash
rustup target add wasm32-unknown-unknown
cargo install --locked trunk        # or: cargo binstall trunk
```

## The cut

One clock. The front end owns `progress` (0 → 1 over 0.92 s, and 1 at rest),
paints its own blocks with it, and hands it to the renderer every frame:

```js
world.set_deck(from, to, progress);   // the renderer is a pure function of this
```

The world cannot drift out of sync with the page, because there is only one
number. Three things happen in sequence:

1. **0 → 0.42, the tear.** Blocks converge, grow, blur and burn out; a stack of
   full-width glass bands rips sideways out of the frame, alternating direction;
   the type splits into a red and a cyan copy. In the world, every piece is
   thrown along its own radial direction, the plates stretch into streaks and the
   rings flare.
2. **0.42, the impact.** A flash frame, a shockwave ring expanding from the
   centre, and the peak of the world's burst: brightest emissive, widest view,
   most camera roll.
3. **0.42 → 1, the landing.** The new page punches in oversized and snaps back,
   block by block down the column, behind one wipe of light. In the world, the
   pieces converge past their marks and settle.

`prefers-reduced-motion` skips all of it: the slide simply changes.

## The world

**One pool, four arrangements.** 176 glass pieces — a core, three hairline rings
and 172 plates cut from a seven-sided shard. Each slide is a different
arrangement of that same pool: an orbit for the hero, three columns over a field
of fallen plates for experience, a lattice of tiles for projects, concentric
rings around a signal for contact. A slide change flies every piece from one
arrangement to the next, which *is* the transition.

**Scale is fixed by the camera.** At a slide the camera sits about 4.4 m from the
arrangement with a 42° view, so one metre is roughly 270 px on a 900 px-tall
frame. Arrangements are built inside a box about 2.0 m wide and 1.5 m tall, and
the camera aims left of that box so the structure reads right of centre and the
document keeps the left. `renderer/src/layout.rs` holds both the geometry and
that convention.

**Material.** One fragment shader, two pipelines. The core and the rings are
opaque and write depth; the plates are blended, sorted back to front on the CPU
each frame, and deliberately thin, so they add light along their edges instead of
darkening the sea behind them. The canvas is transparent (premultiplied) and
composited over the video: there is no sky pass and no shadow map, because the
film is the background and the world is the glass in front of it.

**Type in the world.** Three small labels (a span of years, an index line, a
position) are ordinary DOM elements whose `transform` and `font-size` are driven
from the renderer's per-frame anchor projection, so they stay crisp, selectable
and translatable while appearing to sit in the space. They annotate; they never
repeat what the document says.

## The film

The background is generated for this page and committed as an encoded asset:

```bash
rustc -O -C target-cpu=native tools/loopgen.rs -o /tmp/loopgen
/tmp/loopgen > loop.rgb
ffmpeg -f rawvideo -pix_fmt rgb24 -s 1280x720 -r 24 -i loop.rgb \
  -vf "hqdn3d=2:2:8:8,scale=1024:576" -c:v libx264 -crf 25 -preset slower \
  -tune film -movflags +faststart -an public/film/loop.mp4
```

It is seamless without a cross-fade: every wave component advances by a whole
number of cycles per loop, and each is filtered out as its wavelength approaches
the pixel pitch, which is what keeps the far water smooth instead of aliased.

## Graceful degradation

- **No WebGPU**: the canvas is removed, the film is graded darker, and a faint
  accent grid stands in for the world. Nothing is hidden or duplicated.
- **No scripting**: the four slides stay in the document flow as a plain,
  scrollable portfolio, with the projects list repeated in a `<noscript>` block.
- **`prefers-reduced-motion`**: the film pauses on its poster and slide changes
  are instant.
- **Print**: a plain, ordered document.

## Development notes

- `cargo check --target wasm32-unknown-unknown -p xdm67x-world` for a fast
  renderer check without a wasm build.
- On a local server the deck exposes a few handles:
  `__deck()` (state), `__go(i)` (navigate), `__hold(p)` (freeze the cut at a
  progress value, for inspecting one frame) and `__release()`.
- `scripts/shoot.mjs` is a small Chrome DevTools Protocol driver used while
  building (screenshots at a viewport, with an optional expression evaluated
  first, so a mid-transition frame can be captured). It is not part of the site
  and needs Node.

## Deployment

Pushed to `main` → GitHub Actions installs Rust + Trunk, runs
`trunk build --release`, and publishes `dist/` to GitHub Pages
(<https://xdm67x.github.io>).
